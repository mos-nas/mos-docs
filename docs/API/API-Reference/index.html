📚 MOS API Reference

This is the complete, interactive reference for the MOS REST API. It mirrors the built-in Swagger UI at http://<MOS-IP>/api-docs/ and covers every endpoint, parameter, request/response schema and example request.

Authentication

Most endpoints require a Bearer token. Create one in the WebUI under User Settings → Admin API Tokens, then send it in the Authorization header:

Authorization: Bearer <TOKEN>

Authentication. User authentication and management

GET /auth/firstsetup. Get first setup token. Returns the boot token if it exists in the token file, otherwise returns null. Used for initial system setup. This endpoint requires no authentication. Responses: 200, 500.

POST /auth/login. User login. Body: username, password. Responses: 200, 400, 401, 429.

POST /auth/mfa. Verify MFA code during login. Verify TOTP code or recovery code to complete MFA login. Accepts the temporary mfa token from login response. If recovery code is used, MFA is automatically disabled. Body: mfa_token, code. Responses: 200, 401.

DELETE /auth/mfa. Disable MFA. Disable MFA for the authenticated user. Requires password confirmation. Removes all MFA data. Body: password. Responses: 200, 400, 401.

POST /auth/mfa/setup. Setup or confirm MFA. Two-step MFA setup: - Without code: Generates TOTP secret, returns QR code and secret for manual entry - With code: Verifies TOTP code and activates MFA, returns recovery code Password is always required for security. Body: password, code. Responses: 200, 400, 401.

GET /auth/users. Get users (admin sees all, user sees only themselves). Retrieve users - admins can see all users with optional filtering, normal users only see their own profile (both return arrays) Parameters: samba_user. Responses: 200, 401, 500.

POST /auth/users. Create new user (admin only). Body: username, password, role, samba_user. Responses: 201, 400, 401, 403.

PUT /auth/users/{id}. Update user (admin can update any user, users can update themselves). Update user information - admins can update any user, normal users can only update their own profile with limited fields Parameters: id. Body: username, password, role, samba_user. Responses: 200, 400, 401, 403.

DELETE /auth/users/{id}. Delete user (admin only). Parameters: id. Responses: 204, 400, 401, 403.

GET /auth/profile. Get own user profile. Responses: 200, 401, 404, 500.

POST /auth/logout. User logout. Invalidate the current session. Note that JWT tokens cannot be truly invalidated server-side, but this endpoint provides a consistent logout mechanism. Responses: 200, 401.

GET /auth/jwt-settings. Get JWT settings. Retrieve current JWT token expiry settings (admin only) Responses: 200, 401, 403, 500.

PUT /auth/jwt-settings. Update JWT expiry time. Update JWT token expiry time in days (admin only) Body: expiryDays. Responses: 200, 400, 401, 403, 500.

GET /auth/admin-tokens. Get all admin tokens. Retrieve list of all admin API tokens (admin only) Responses: 200, 401, 403, 500.

POST /auth/admin-tokens. Create admin token. Create a new permanent admin API token (admin only) Body: name, description, permissions. Responses: 201, 400, 401, 403, 500.

GET /auth/admin-tokens/me. Get current token permissions. Introspect the permissions of the token used for this request. Only reachable when authenticated with an API token (boot token or admin token). Responses: 200, 401, 403.

PUT /auth/admin-tokens/{id}/permissions. Update admin token permissions. Update the permission scope of an existing admin API token (admin only) Parameters: id. Body: permissions. Responses: 200, 400, 401, 403, 500.

DELETE /auth/admin-tokens/{id}. Delete admin token. Permanently delete an admin API token (admin only) Parameters: id. Responses: 200, 400, 401, 403, 500.

PUT /auth/admin-tokens/{id}/deactivate. Deactivate admin token. Deactivate an admin API token without deleting it (admin only) Parameters: id. Responses: 200, 400, 401, 403, 500.

Disks. Disk and Storage Management

GET /disks. List all disks with partitions. Retrieve a comprehensive list of all disks with their partitions and power status. Uses live data without caching. Parameters: performance, skipStandby. Responses: 200, 401, 500.

GET /disks/{device}/usage. Get disk usage statistics. Retrieve usage statistics for a specific disk or partition using df command Parameters: device. Responses: 200, 401, 500.

GET /disks/{device}/power. Get disk power status. Retrieve the current power status of a specific disk Parameters: device. Responses: 200, 401, 500.

GET /disks/{device}/iostats. Get disk I/O statistics. Retrieve I/O statistics for a specific disk Parameters: device. Responses: 200, 401, 500.

POST /disks/{device}/wake. Wake disk from standby. Wake a disk from standby or sleep mode (admin only) Parameters: device. Responses: 200, 401, 403, 500.

POST /disks/{device}/sleep. Put disk to sleep/standby. Put a disk into standby or sleep mode (admin only) Parameters: device. Body: mode. Responses: 200, 400, 401, 403, 500.

GET /disks/{device}/smart. Get SMART information. Retrieve comprehensive SMART data for a specific disk. Data is sourced from smartd state files (no disk I/O) or smartctl (live). If the disk is sleeping, all SMART fields are null unless wakeUp=true is specified. Response structure is always consistent - fields are null when unavailable. Parameters: device, wakeUp. Responses: 200, 401, 500.

GET /disks/descriptions/orphaned. List orphaned disk descriptions. Get all disk descriptions whose disk is no longer physically present Responses: 200, 500.

DELETE /disks/descriptions/orphaned. Delete all orphaned disk descriptions. Remove all descriptions whose disk is no longer physically present (admin only) Responses: 200, 403, 500.

DELETE /disks/descriptions/orphaned/{serial}. Delete a specific orphaned disk description. Remove a single description by serial number, only if the disk is not currently present (admin only) Parameters: serial. Responses: 200, 403, 404, 500.

PUT /disks/{device}/description. Set or clear a disk description. Set a user-defined description for a disk. The description is stored persistently keyed by the disk's serial number (survives device name changes). An empty or null description removes the entry. The config file is only written on change (admin only). Parameters: device. Body: description. Responses: 200, 400, 403, 500.

GET /disks/availablefilesystems. Get available filesystems. Retrieve a simple array of available filesystem names for formatting. Use the pooltype parameter to filter filesystems based on pool type: - multi : Returns only btrfs and zfs (if available) - these support multiple disks - nonraid , single , mergerfs or no parameter: Returns all available filesystems Parameters: pooltype. Responses: 200, 401, 500.

POST /disks/format. Format disk/device. Format a disk or device with specified filesystem (admin only) Body: device, filesystem, partition, wipeExisting, preClear. Responses: 200, 400, 401, 403, 500.

POST /disks/{device}/preclear/abort. Abort preClear operation. Abort a running preClear operation on a device (admin only). The disk will be left in an undefined state. Parameters: device. Responses: 200, 400, 401, 403, 500.

POST /disks/{device}/partition. Create partition. Create a new partition on the specified device (admin only) Parameters: device. Responses: 200, 401, 403, 500.

DELETE /disks/{device}/partition/{partitionNumber}. Delete partition. Delete a specific partition from a device (admin only) Parameters: device, partitionNumber. Responses: 200, 401, 403, 500.

DELETE /disks/{device}/wipe. Wipe entire disk. Completely wipe a disk, removing all partitions and data (admin only) Parameters: device. Responses: 200, 401, 403, 500.

GET /disks/{device}/partitions. Get disk partitions. Retrieve all partitions for a specific disk Parameters: device. Responses: 200, 401, 500.

POST /disks/wake. Wake multiple disks. Wake multiple disks from standby simultaneously (admin only) Body: devices. Responses: 200, 400, 401, 403, 500.

POST /disks/sleep. Sleep multiple disks. Put multiple disks to sleep/standby simultaneously (admin only) Body: devices, mode. Responses: 200, 400, 401, 403, 500.

POST /disks/power/status. Get power status for multiple disks. Get power status for multiple disks simultaneously (admin only) Body: devices. Responses: 200, 400, 401, 403, 500.

POST /disks/power/manage. Manage disk power settings. Configure power management settings for a disk (admin only) Body: device, check. Responses: 200, 400, 401, 403, 500.

GET /disks/unassigned. List unassigned disks. Retrieve a list of disks that are not assigned to any pool or array and are not system disks Parameters: includePerformance, skipStandby. Responses: 200, 401, 500.

POST /disks/{device}/mount. Mount a disk device. Mount a single disk device or partition to /mnt/disks/ with automatic mountability checks (admin only) Parameters: device. Body: mountOptions. Responses: 200, 400, 401, 403, 500.

POST /disks/{device}/unmount. Unmount a disk device. Unmount a single disk device or partition, handles BTRFS multi-device properly (admin only) Parameters: device. Body: force, lazy. Responses: 200, 401, 403, 500.

GET /disks/zram/ramdisks. Get ZRAM ramdisk devices. Returns all active ZRAM ramdisk devices (type=ramdisk, enabled=true) that can be used as storage pools Responses: 200, 401, 500.

SMART. SMART Monitoring Configuration and Status

GET /disks/smart/config. Get SMART monitoring configuration. Retrieve the complete SMART monitoring configuration including defaults, per-disk settings, and orphaned entries Responses: 200, 500.

PUT /disks/smart/config. Update global SMART configuration. Update global SMART settings (defaults, smartdOptions). Supports partial updates via deep merge - only send the fields you want to change. After update, smartd.conf is regenerated and smartd reloaded. Note: Use the per-disk endpoints to manage individual disk configurations. Body: defaults, smartdOptions. Responses: 200, 400, 403, 500.

GET /disks/smart/config/disks/{device}. Get SMART config for a specific disk. Retrieve the monitoring configuration for a disk by device name (e.g. sda) or serial number Parameters: device. Responses: 200, 404, 500.

PUT /disks/smart/config/disks/{device}. Update SMART config for a specific disk. Update monitoring settings for a specific disk by device name or serial. Supports partial updates - only send the fields you want to change. After update, smartd.conf is regenerated. Parameters: device. Body: temperatureWarning, temperatureCritical, monitoredAttributes, attributeNotificationCooldown. Responses: 200, 400, 403, 404, 500.

DELETE /disks/smart/config/disks/{device}. Delete disk SMART config. Remove custom configuration for a disk by device name or serial. The disk will be re-added with default settings on the next sync if still present. Parameters: device. Responses: 200, 403, 404, 500.

POST /disks/smart/config/disks/{device}/acknowledge. Acknowledge current SMART errors for a disk. Acknowledge the current raw values of a disk's monitored SMART attributes as a baseline. Unlike removing an attribute from monitoring ("ignore"), acknowledged errors stay visible (the disk keeps warning=true) but no further boot/live notifications are sent until a value rises above its acknowledged baseline. Values are taken from the cached smartd state (no disk wakeup). Send an empty body to acknowledge all currently reported attributes, or { attributes: [187] } to acknowledge a specific attribute at its current value (no number needed). A baseline can also be cleared inline by sending "" or null for an attribute under "acknowledged"; to clear baselines explicitly use DELETE on the same path. Parameters: device. Body: attributes, acknowledged. Responses: 200, 400, 403, 404, 500.

DELETE /disks/smart/config/disks/{device}/acknowledge. Clear acknowledged SMART errors for a disk. Remove acknowledgement baselines for a disk. Send an empty body to clear all baselines, or { attributes: [...] } to clear only specific attribute IDs. After clearing, the normal boot/live notification behaviour applies again for those attributes. Parameters: device. Body: attributes. Responses: 200, 400, 403, 404, 500.

GET /disks/smart/config/orphaned. List orphaned disk entries. Get all disk configurations that were previously known but the disk is no longer physically present Responses: 200, 500.

DELETE /disks/smart/config/orphaned. Delete all orphaned entries. Remove all orphaned disk configuration entries at once Responses: 200, 403, 500.

DELETE /disks/smart/config/orphaned/{serial}. Delete a specific orphaned entry. Remove a single orphaned disk configuration entry by serial number Parameters: serial. Responses: 200, 403, 404, 500.

Disks WebSocket. Real-time disk monitoring via WebSocket

GET /disks/websocket/stats. Get Disks WebSocket monitoring statistics. Responses: 200, 401, 500.

GET /disks/websocket/events. Disks WebSocket Events Documentation. This endpoint documents the WebSocket events for real-time disk monitoring. Connection: Connect to WebSocket at /disks namespace with path /api/v1/socket.io/ Events to emit (client → server): - subscribe-disks: Subscribe to disk throughput and temperature updates - unsubscribe-disks: Unsubscribe from disk updates - get-disks: Get immediate disk data (one-time) Events to listen for (server → client): - disks-update: Real-time throughput data (every 2s) - disks-temperature-update: Temperature data (every 10s if includeTemperature=true) - disks-subscription-confirmed: Subscription confirmation - disks-unsubscription-confirmed: Unsubscription confirmation - error: Error messages Important Notes: - Standby disks are NOT woken up for temperature queries - Throughput comes from /proc/diskstats (no disk wake-up) - Temperature uses smartctl -n standby (safe for standby disks) Example Usage: Connect to WebSocket: const socket = io('http://localhost:3000/disks', { path: '/api/v1/socket.io/' }); Subscribe to all disks with temperature: socket.emit('subscribe-disks', { token: 'your-jwt-token', devices: [], // empty = all disks includeTemperature: true }); Subscribe to specific disks: socket.emit('subscribe-disks', { token: 'your-jwt-token', devices: ['sda', 'sdb'], includeTemperature: false }); Listen for updates: socket.on('disks-update', (data) = { console.log('Throughput:', data.throughput); }); socket.on('disks-temperature-update', (data) = { console.log('Temperatures:', data.temperatures); }); Responses: 200.

Pools. Storage Pool Management

GET /pools/vpools. List all vpools (MergerFS Path Pools). List all MergerFS Path Pools with mount status and storage info. Storage is reported from a single df on the mergerfs union mount, like regular pools. Responses: 200, 500.

POST /pools/vpools. Create a vpool (MergerFS Path Pool). Create a new MergerFS Path Pool by unioning existing filesystem paths under /mnt/{name}. The name must be globally unique (across pools and vpools) and must not be a reserved name. When automount is enabled (default), the pool is mounted immediately; all configured paths must exist as directories. Body: name, paths, automount, comment, config. Responses: 201, 400, 403.

PUT /pools/vpools/order. Update vpool display order. Update the display order (index) of vpools (admin only) Body: order. Responses: 200, 400, 500.

GET /pools/vpools/{id}. Get a vpool by ID. Parameters: id. Responses: 200, 404.

DELETE /pools/vpools/{id}. Delete a vpool by ID. Unmount (if mounted) and remove the vpool from vpools.json. Source paths are never deleted. Fails if the pool is in use unless force is set (admin only). Parameters: id. Body: force. Responses: 200, 400, 404.

POST /pools/vpools/{id}/mount. Mount a vpool by ID. Mount the mergerfs union at /mnt/{name}. All configured source paths are validated first; if any path is missing or not a directory, the mount is aborted with an error. Parameters: id. Responses: 200, 400, 404.

POST /pools/vpools/{id}/unmount. Unmount a vpool by ID. Unmount the mergerfs union at /mnt/{name}. Source paths are left untouched. Parameters: id. Body: force. Responses: 200, 400, 404.

POST /pools/vpools/{id}/automount. Toggle automount for a vpool. Enable or disable automount (flag only, does not mount/unmount) (admin only) Parameters: id. Body: enabled. Responses: 200, 400, 500.

GET /pools. List all pools. Get a list of all storage pools with optional filtering, performance and temperature data Parameters: type, exclude_type, includeMetrics. Responses: 200, 500.

GET /pools/availablepooltypes. Get available pool types. Retrieve a simple array of available pool types. Responses: 200, 401, 500.

GET /pools/{id}. Get pool by ID. Get a specific pool by its ID Parameters: id. Responses: 200, 404.

DELETE /pools/{id}. Remove pool by ID. Remove a storage pool Parameters: id. Responses: 200, 404.

GET /pools/{id}/status. Get pool status. Get the current status of a pool Parameters: id. Responses: 200, 404, 500.

POST /pools/{id}/automount. Toggle automount setting for a pool. Enable or disable automatic mounting of a pool on system boot (admin only) Parameters: id. Body: enabled. Responses: 200, 400, 404, 500.

POST /pools/{id}/shared. Toggle shared mount propagation for a pool. Enable or disable shared mount propagation (mount --make-shared / --make-private) live without remounting; the setting is persisted and reapplied on mount (admin only) Parameters: id. Body: enabled. Responses: 200, 400, 404, 500.

PATCH /pools/{id}/comment. Update pool comment. Update the comment/description for a storage pool (admin only) Parameters: id. Body: comment. Responses: 200, 400, 404, 500.

GET /pools/{id}/config. Get pool configuration. Retrieve the configuration settings for a specific pool Parameters: id. Responses: 200, 404, 500.

PATCH /pools/{id}/config. Update pool configuration. Update configuration settings for a pool (works for all pool types - mergerfs, btrfs, xfs, etc.) Supports dot-notation for nested properties: - Direct: { "unclean check": false } - Nested: { "sync.enabled": true, "sync.schedule": "0 5 " } Parameters: id. Body: unclean_check, encrypted, raid_level, shared, sync.enabled, sync.schedule, usage_alert.warning, usage_alert.alert, spindown. Responses: 200, 404, 500.

PUT /pools/order. Update order of all pools. Update the display order for multiple pools at once by providing an array of pool IDs with their new index values (admin only) Body: order. Responses: 200, 400, 500.

POST /pools/single. Create single device pool. Create a new single device pool Body: name, device, filesystem, format, config, passphrase, options. Responses: 201, 400, 403.

POST /pools/multi. Create multi-device BTRFS pool. Create a new multi-device BTRFS pool Body: name, devices, raidLevel, format, config, passphrase, options. Responses: 201, 400, 403.

POST /pools/mergerfs. Create MergerFS pool. Create a new MergerFS pool Body: name, devices, filesystem, format, config, passphrase, options, skip_size_check. Responses: 201, 400, 403.

POST /pools/bcachefs. Create bcachefs pool. Creates a bcachefs pool. bcachefs is a native multi-device filesystem, so redundancy is a configuration property instead of a dedicated parity disk and parity devices stays empty. Redundancy maps to RAID levels as follows: - data replicas: 1 - striping without redundancy (RAID 0) - data replicas: 2 - mirroring (RAID 1/10) - data replicas: 2 + erasure code: true - single parity (RAID 5) - data replicas: 3 + erasure code: true - double parity (RAID 6) Cache devices are passed separately and get the ssd device group, data devices get hdd. Requires the bcachefs kernel module from the mos-bcachefs plugin. Body: name, devices, cache_devices, format, config, passphrase, options. Responses: 201, 400, 403.

POST /pools/nonraid. Create NonRAID pool. Create a new NonRAID pool with optional parity devices (max 2). Important: - Only one NonRAID pool per system - Parity check runs automatically after creation unless parity valid is true - When parity valid is true, parity is marked as valid and no check runs Body: name, devices, filesystem, format, parity, parity_valid, config, passphrase, options. Responses: 201, 400, 403.

POST /pools/nonraid/replace. Replace devices in a NonRAID pool. Replace one or more devices in the NonRAID pool with parity reconstruction (admin only). Important: - Only one NonRAID pool can exist per system - Pool must be unmounted before replacement - Maximum replacements: 1 device with 1 parity, 2 devices with 2 parities - Data and parity devices can be replaced simultaneously - Parity reconstruction starts automatically after replacement Size Requirements: - New data devices must be <= smallest parity device - New parity devices must be = largest data device Encryption: - Passphrase required when replacing data devices in encrypted pools - New data devices will be encrypted with the existing key Body: replacements, format, passphrase. Responses: 200, 400, 403, 404, 500.

POST /pools/nonraid/adddevice. Add data device to NonRAID pool. Add a new data device to the NonRAID pool (admin only). Device will be assigned the next available slot (1-28) automatically. Modes: - format: true - Create partition and format device with specified filesystem - format: false - Import existing partition/filesystem (device must have usable filesystem) Important: - Pool must be unmounted before adding device - Not possible while a parity operation (check, clear, rebuild) is running - Pool is mounted automatically after the device was added - With parity and format: true the disk is cleared (zeroed) in the background first, then formatted and added to the pool. The array stays usable; notifications are sent on start and when the disk is ready - format: false runs a parity check unless parity valid is true - parity valid: true skips clearing/check (disk must already be zeroed) - Passphrase required for encrypted pools without keyfile - Adding, replacing or adding parity is rejected until a new disk is cleared, formatted and ready Size Requirements: - New data device must be <= smallest parity device Body: device, format, filesystem, passphrase, parity_valid. Responses: 200, 400, 404, 500.

POST /pools/nonraid/addparity. Add parity device to NonRAID pool. Add a new parity device to the NonRAID pool (admin only). Device will be assigned the next available parity slot (1 or 2) automatically. Important: - Pool must be unmounted before adding parity - Not possible while a parity operation (check, clear, rebuild) is running - Pool is mounted automatically after the parity was added - Maximum 2 parity devices allowed - Parity check ALWAYS runs when adding parity - Parity device is NOT formatted Size Requirements: - Parity device must be = largest data device Body: device, passphrase. Responses: 200, 400, 404, 500.

POST /pools/{id}/mount. Mount pool by ID. Mount a storage pool Parameters: id. Body: passphrase, mountOptions, mount_missing. Responses: 200, 404.

POST /pools/{id}/unmount. Unmount pool by ID. Unmount a storage pool Parameters: id. Body: force. Responses: 200, 404.

POST /pools/{id}/devices. Add devices to pool. Add new devices to an existing pool Parameters: id. Body: devices, format, group. Responses: 200, 404.

POST /pools/{id}/parity/add. Add parity devices to a MergerFS pool. Add one or more parity devices to an existing MergerFS pool for SnapRAID protection (admin only). Devices will be formatted if needed and SnapRAID configuration will be updated. Parameters: id. Body: devices, format, skip_size_check. Responses: 200, 400, 404, 500.

POST /pools/{id}/parity/replace. Replace a parity device in a MergerFS pool. Replace an existing parity device with a new one in a MergerFS pool (admin only). The old device will be unmounted and the new device will take over its parity slot. SnapRAID configuration will be updated automatically. Size Requirements (default): - New parity device must be = largest data device - Use skip size check to bypass this validation Encryption: - For encrypted pools, the new device will be encrypted with the existing key - Passphrase is required for encrypted pools Parameters: id. Body: oldDevice, newDevice, format, passphrase, skip_size_check. Responses: 200, 400, 404, 500.

POST /pools/{id}/parity/remove. Remove parity devices from a MergerFS pool. Remove one or more parity devices from an existing MergerFS pool (admin only). If all parity devices are removed, SnapRAID configuration will be cleaned up. Parameters: id. Body: devices, unmount. Responses: 200, 400, 404, 500.

POST /pools/{id}/devices/remove. Remove devices from an existing pool. Remove one or more devices from an existing MergerFS, BTRFS or bcachefs pool (admin only). Will update SnapRAID config if pool has SnapRAID configured. bcachefs: The pool must be mounted. Data is evacuated onto the remaining devices before removal, which can take hours on large devices, so it runs in the background and notifications are sent on start and completion. The remaining devices must still satisfy data replicas/erasure coding, and the last cache device cannot be removed while a cache mode is configured. Only one device operation per bcachefs pool can run at a time. Parameters: id. Body: devices, unmount. Responses: 200, 400, 401, 403, 404, 500.

POST /pools/{id}/devices/add. Add devices to an existing pool. Add one or more devices to an existing pool (admin only). BTRFS Pools: - Single-device pools (type 'btrfs') will automatically be converted to multi-device with raid1 configuration - Uses native BTRFS device addition functionality - Pool must be mounted for the operation MergerFS Pools: - Devices will be mounted individually and added to the MergerFS union - Will format devices if needed and update SnapRAID config if pool has SnapRAID configured - Pool will be remounted automatically after device addition bcachefs Pools: - Devices join the mounted filesystem online, format must be true - group selects data (hdd) or cache (ssd), cache durability follows the pool's cache mode Parameters: id. Body: devices, format, passphrase, group. Responses: 200, 400, 401, 403, 404, 500.

POST /pools/{id}/devices/replace. Replace a device in a pool. Replace a data device of a BTRFS, MergerFS or bcachefs pool (admin only). bcachefs Pools: - The pool must be mounted and format must be true - The new device joins first in the group of the old one, then the old device is evacuated and removed, so redundancy never drops during the replacement - The old device must still be reachable, evacuation can take hours on large devices and runs in the background, notifications are sent on start and completion Parameters: id. Body: oldDevice, newDevice, format, passphrase. Responses: 200, 404, 500.

POST /pools/{id}/parity. Execute parity operation on a MergerFS or NonRAID pool. Execute parity operations on pools with parity devices (admin only). MergerFS Pools (SnapRAID): - Operations: sync, check, scrub, fix, status, force stop NonRAID Pools: - Operations: check, pause, resume, cancel, auto - For 'check': use 'option' parameter (CORRECT or NOCORRECT) - 'auto': Automatically starts check (NOCORRECT) if not running, or cancels if running Parameters: id. Body: operation, option, fixDisks. Responses: 200, 400, 404, 500.

POST /pools/{id}/btrfs/scrub. Execute BTRFS scrub operation. Scrub operations for BTRFS pools only. Operations: - start: Start a new scrub (fails if one is already running) - status: Get current scrub status and progress - pause: Pause a running scrub (via cancel in BTRFS) - cancel: Cancel a running scrub Parameters: id. Body: operation. Responses: 200, 400, 404, 500.

POST /pools/{id}/btrfs/balance. Execute BTRFS balance operation. Balance operations for BTRFS pools only. Operations: - start: Start a new balance (optionally with RAID conversion) - status: Get current balance status and progress - pause: Pause a running balance - cancel: Cancel a running or paused balance Parameters: id. Body: operation, raidLevel. Responses: 200, 400, 404, 500.

POST /pools/{id}/bcachefs/scrub. Execute bcachefs scrub operation. Scrub operations for bcachefs pools only. A scrub verifies all data checksums and repairs from redundant copies where possible; affected paths are logged to dmesg. Operations: - start: Start a new scrub (fails if one is already running) - status: Get current scrub status and progress - cancel: Stop a running scrub (bcachefs has no pause) Parameters: id. Body: operation. Responses: 200, 400, 404, 500.

Pools WebSocket. Real-time pool monitoring via WebSocket

File Operations WebSocket. File Operations WebSocket

GET /mos/fileoperations/websocket/events. WebSocket Events Documentation. This endpoint documents the WebSocket events for real-time file operation monitoring. Connection: Connect to WebSocket at /api/v1/fileoperations namespace Events to emit (client → server): - subscribe-operation - Subscribe to a specific operation by ID - subscribe-all - Subscribe to all file operations - unsubscribe-operation - Unsubscribe from a specific operation - unsubscribe-all - Unsubscribe from all file operations - update-preferences - Update byte format preference Events to listen for (server → client): - fileoperations-update - Progress update for a single operation - fileoperations-list - All operations (sent on subscribe-all) - fileoperations-subscription-confirmed - Subscription confirmed - fileoperations-unsubscription-confirmed - Unsubscription confirmed - preferences-updated - Preferences updated confirmation - error - Error occurred Update Interval: Progress updates are broadcast every 2 seconds. State changes (completed, failed, cancelled) are sent immediately. Important: Operations continue running in the background even when no WebSocket clients are connected. The WebSocket is only for monitoring. Operations are started and cancelled via REST endpoints. Example Usage: Connect to WebSocket: const socket = io('http://localhost:998/api/v1/fileoperations', { path: '/api/v1/socket.io/' }); Subscribe to a specific operation: socket.emit('subscribe-operation', { token: 'your-jwt-token', operationId: '1742742123456' }); Subscribe to all operations: socket.emit('subscribe-all', { token: 'your-jwt-token' }); Listen for updates: // Single operation update (progress, status changes) socket.on('fileoperations-update', (data) = { console.log([${data.id}] ${data.operation} ${data.status}); console.log( Progress: ${data.progress}%); console.log( Speed: ${data.speed human}); console.log( ETA: ${data.eta}); console.log( ${data.bytesTransferred human} / ${data.bytesTotal human}); if (data.instantMove) { console.log(' Instant move (same filesystem)'); } if (data.status === 'completed') { console.log(' Completed at:', data.completedAt); } if (data.status === 'failed') { console.error(' Error:', data.error); } }); // All operations list (sent on subscribe-all) socket.on('fileoperations-list', (operations) = { console.log(${operations.length} operations); operations.forEach(op = { console.log( ${op.id}: ${op.operation} ${op.status} ${op.progress}%); }); }); Update byte format preference: socket.emit('update-preferences', { byte format: 'decimal' }); Unsubscribe: socket.emit('unsubscribe-operation', { operationId: '1742742123456' }); socket.emit('unsubscribe-all'); Responses: 200.
